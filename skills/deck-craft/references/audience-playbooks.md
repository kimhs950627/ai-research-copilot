# 청중별 플레이북

같은 내용도 청중이 바뀌면 순서·강조·어휘가 바뀐다. `deck.json` 의 `meta.audience` 로 하나를 고르고
아래 필수 요소를 대조한다.

## 1. 학회 · 학술대회 (`academic`)

**목표**: 동료 심사자 관점에서 방법과 결과를 신뢰하게 만든다.

필수 슬라이드:

1. `cover` — 제목, 저자 전체, 소속, 이해상충(COI) 1줄
2. `claim` — 연구질문 한 문장 ("A는 B에서 C보다 우수한가")
3. `evidence` — 방법: 설계, 대상 수(N), 기간, 무작위/맹검 여부
4. `evidence` — 결과 1: 주 결과, **효과크기 + 95% CI + p**
5. `evidence` — 결과 2: 부차 결과·하위군(있다면)
6. `compare` — 기존 문헌과의 비교
7. `claim` — 한계(Limitations): 3–4개, 숨기지 않는다
8. `claim` — 결론 + 임상적 함의 한 문장
9. `appendix` — 참고문헌, 추가 도표

금기: "혁신적인 치료", "획기적", 인과 확정("~을 예방한다") — 관찰연구면 "연관", "~와 관련".
표기: 수치는 단위·자릿수 통일(`12.3% (95% CI 9.1–16.4)`), p값은 소수 셋째 자리까지.
질문 대비: 표본수 근거, 탈락률, 민감도 분석을 부록에 준비.

## 2. 기업 · 경영진 (`corporate`)

**목표**: 의사결정(승인·예산·우선순위)을 끌어낸다.

필수 슬라이드:

1. `cover`
2. `claim` — 한 문장 결론(가장 먼저 말한다: BLUF)
3. `kpi` — 핵심 수치 2–3개
4. `claim` — 문제와 그 비용(연간 손실·기회비용, 산식 명시)
5. `compare` — 대안 2–3개와 평가 기준
6. `timeline` — 실행 일정과 마일스톤
7. `evidence` — 재무: 투자, 회수 기간, 주요 가정(민감도 1장)
8. `claim` — 리스크와 대응
9. `closing` — 요청(승인 항목·금액·기한)을 명시

금기: 출처 없는 시장 규모, "업계 1위", 근거 없는 성장률. 가정은 슬라이드에 쓰고 각주에 산식을 둔다.
질문 대비: 단가 산정 근거, 인력 계획, 실패 시나리오.

## 3. 정부 · 공공기관 (`government`)

**목표**: 사업의 필요성·법적 근거·집행 계획을 납득시킨다.

필수 슬라이드:

1. `cover` — 사업명, 부서, 일자
2. `claim` — 정책 목표와 상위 계획과의 연결(국정과제·조례 등 근거 조항)
3. `evidence` — 현황 지표: 현재 값, 목표 값, 출처(통계 연도)
4. `flow` — 추진 절차(각 단계 산출물·승인 주체)
5. `timeline` — 연차별 일정
6. `evidence` — 소요 예산(항목·산출 근거)과 재원
7. `kpi` — 성과지표와 측정 방법(누가·언제·어떻게)
8. `claim` — 기대효과(과장 없이)와 부작용·대응
9. `appendix` — 이해관계자 의견수렴 결과, 참고 법령

금기: 정치적 수사, 근거 없는 효과 추정, 출처 없는 통계. 숫자는 **출처 기관·연도**를 슬라이드 안에.
질문 대비: 예산 산출 근거, 유사사업 대비 차별점, 중단 기준.

## 4. 교육 · 강의 (`education`)

**목표**: 학습자가 끝나고 무엇을 할 수 있게 되는가.

필수 슬라이드:

1. `cover` — 제목, 대상, 소요 시간
2. `claim` — 학습목표 3개("이 강의가 끝나면 ~할 수 있다")
3. `agenda` — 결론이 붙은 목차
4. 본문: 개념 → 예시 → **직접 해보기** → 정리 (15분마다 요약 1장)
5. `claim` — 흔한 오해 2–3개와 교정
6. `claim` — 요약(학습목표와 1:1 대응)
7. `appendix` — 확인 문제 + 답, 더 읽을거리

금기: 한 슬라이드 다량 텍스트(강의 자료는 더 조밀해도 되지만 40단어/슬라이드 상한 유지),
정의만 나열. 모든 개념에 예시나 숫자를 하나 붙인다.

## 5. 내부 보고 · 팀 (`internal`)

**목표**: 진행 상황과 막힌 지점을 공유하고 결정을 받는다.

1. `claim` — 이번 주 결론(잘 된 것 / 막힌 것 / 필요한 결정)
2. `kpi` — 진척 지표
3. `claim` — 막힌 지점과 요청 사항(담당·기한)
4. `timeline` — 다음 스프린트

금기: 활동 나열("회의 3회"), 결론 없는 진행률. "무엇을 결정해 달라"를 항상 명시.

## 6. 공통 체크

- 발표장 **뒤에서** 읽히는가? (본문 ≥ 24pt)
- 첫 30초에 결론을 말했는가?
- 마지막 장에 **요청**이 있는가?
- 모든 숫자에 단위·기간·출처가 있는가?
- 청중이 물을 3가지를 예상해 부록에 준비했는가?
