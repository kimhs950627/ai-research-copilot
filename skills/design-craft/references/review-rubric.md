# 리뷰 루브릭 — 넘기기 전에 판정하는 기준

리뷰는 **스크린샷을 실제로 본 뒤**에만 한다. 코드만 읽고 "괜찮아 보인다"고 하지 않는다.

## 순서

1. `design-lint.py <src-dir>` → HIGH 0건 확인 (기계적 신호).
2. `page-check.sh <url|file>` → 오버플로·대비·작은 텍스트·alt·제목 계층 (기하/접근성, 눈 불필요).
3. `shot.sh` 로 1440 / 375 (+ 매체 캔버스) 스크린샷 → 실제 렌더 확인.
4. 아래 루브릭으로 항목별 판정.
5. 보고는 등급별로 묶어서. **수정은 사용자가 승인한 뒤에만** (리뷰만 요청받았으면 지적만).
6. 필요하면 `web-guidelines.sh` 로 최신 웹 인터페이스 규칙을 받아 접근성/일관성 항목을 대조한다.

스크린샷을 볼 수 없는 모델이면 3–4단계를 건너뛰지 말고 **건너뛴 사실을 보고에 쓴다**:
"구성·위계·취향 검증은 이미지 입력 미지원으로 수행하지 못함 — 스크린샷을 첨부하니 직접 확인 요청".

## 등급

| 등급 | 뜻 | 처리 |
|---|---|---|
| 🔴 치명 | 사용 불가·법적/접근성 위반·깨진 화면 | 반드시 수정 |
| 🟠 중요 | 퀄리티를 크게 깎음 (AI 티 신호, 위계 붕괴) | 승인 후 수정 |
| 🟡 제안 | 더 좋아질 여지 | 선택 |

## 1. 위계 · 스캔성

- [ ] 3초 안에 "이 화면이 무엇인지" 읽히는가.
- [ ] 가장 중요한 요소가 가장 크거나 가장 강한가 (두 개가 경쟁하지 않는가).
- [ ] 제목/본문/캡션 위계가 3단계 이상인가.
- [ ] 흑백으로 바꿔도 위계가 유지되는가.
- [ ] 섹션 밀도에 변화가 있는가(꽉 참 ↔ 여백).

## 2. 타이포

- [ ] 폰트 선택 이유를 한 문장으로 말할 수 있는가.
- [ ] measure 45–75자, 행간 1.5–1.7 (본문).
- [ ] 큰 제목 자간이 좁혀져 있는가(-0.01~-0.03em).
- [ ] 한글/영문 혼용 시 기준선·무게가 튀지 않는가.
- [ ] 최소 크기 위반 없음 (본문 16px+, 카드뉴스 32px+, 슬라이드 24pt+).

## 3. 색 · 대비

- [ ] 지배색 1 + 악센트 1 구조인가.
- [ ] 본문 대비 ≥ 4.5:1, 큰 텍스트 ≥ 3:1.
- [ ] 색만으로 정보를 구분하지 않는가(모양·라벨 보조).
- [ ] 보라/인디고 그라디언트 같은 HIGH 신호가 없는가.
- [ ] 다크/라이트 또는 단계형 테마에서 대비가 유지되는가.

## 4. 레이아웃 · 정렬

- [ ] 4/8px 그리드에 정렬되어 있는가 (눈대중 금지).
- [ ] 섹션 상하 여백이 균일하지 않고 의도적으로 다른가.
- [ ] 겹침/오버플로/잘림 0건 (1440·375 모두).
- [ ] 375px 에서 가로 스크롤이 생기지 않는가.
- [ ] 이미지와 배경색 경계가 보이지 않는가(토큰 일치).

## 5. 모션 (있으면)

- [ ] `prefers-reduced-motion` 분기가 있는가.
- [ ] 등장이 한 번에 쏟아지지 않고 순차적(stagger)인가.
- [ ] duration 이 목적에 맞는가 (마이크로 120–200ms, 등장 400–700ms).
- [ ] 스크롤 연동 애니메이션이 스크롤을 방해하지 않는가.
- [ ] `transition: all` 이 없는가.

## 6. 컴포넌트 · 표면

- [ ] 반경·그림자가 토큰에서 오는가(균일 radius/box-shadow 아님).
- [ ] 클릭 요소 hover/active/focus 상태가 모두 정의되어 있는가.
- [ ] `:focus-visible` 링이 보이는가 (outline 제거만 하고 대체 없음 = 🔴).
- [ ] 로딩/빈/에러 상태가 (앱이면) 디자인되어 있는가.

## 7. 콘텐츠 · 카피

- [ ] Lorem/플레이스홀더 0건.
- [ ] "혁신적인/편리한/seamless" 류 빈 문장이 없는가.
- [ ] 구체적 수치·이름·기간이 있는가.
- [ ] 버튼 라벨이 동사 + 목적어인가 ("시작하기" 남발 아님).
- [ ] 텍스트가 데이터 계층에서 오는가.

## 8. 완성도 · 성능

- [ ] 이미지 포맷(webp/avif), 크기 지정(width/height), lazy 로딩.
- [ ] 폰트 서브셋 + `font-display: swap`.
- [ ] `alt` 존재, 제목 계층(h1→h2→h3) 건너뜀 없음.
- [ ] 링크/버튼에 접근 가능한 이름이 있는가.
- [ ] 콘솔 에러 0건, 404 리소스 0건.

## 보고 형식

```
디자인 리뷰 — <산출물 이름> (<매체>)
검증: design-lint HIGH 0 / MED 2 · 스크린샷 1440+375 확인

🔴 치명
- hero.webp 가 375px 에서 잘림 (파일:라인) → object-position 조정
🟠 중요
- Inter 사용으로 AI 티 신호 (tokens.css:4) → 톤에 맞는 폰트 페어로 교체 제안: A / B
- 히어로 → 그리드 사이 브릿지 없음 → 브랜드 메시지 섹션 1개 추가
🟡 제안
- 카드 반경 8px 균일 → 2px/6px 2단계로
남은 선택: <사용자 결정이 필요한 것>
```

규칙:

- 지적에는 **파일:라인**과 **대안**을 함께 쓴다. 대안 없는 지적은 잔소리다.
- 사용자 결정이 필요한 것은 마지막에 따로 모아 묻는다(Kimaki 는 `kimaki buttons`).
- 리뷰만 요청받았으면 파일을 수정하지 않는다.
- 전체 리뷰가 3줄이면 그냥 말로 쓴다. 형식이 내용을 이기지 않게.
