# 색 선택 — 표면마다 새로 정한다 (adaptive palette)

> **먼저 `theme-taxonomy.md` 를 본다.** 색만 고르면 카드·책·덱이 여전히 닮는다(폰트·밀도·질감이 고정이므로).
> 기본 경로는 `theme-advisor.py`(테마 전체)이고, **이 문서는 그 색 부품**이다 — 색 단독이 필요할 때
> `palette-advisor.py` 를 쓴다.

**문제**: 디자인 스킬을 쓸 때마다 같은 색이 나온다. 웜 베이지 표면 + 테라코타 악센트
(`#F4EFE8` / `#B33A0B`)가 카드·덱·책·자료에 반복되고, 대상이 의학이든 요리든 금융이든 결과가 비슷해진다.
이건 **취향 문제가 아니라 절차 문제**다 — 색을 정하는 단계가 파이프라인에 없으면 템플릿 기본값이 그대로
출력된다.

**해법**: 색을 **매 산출물마다 입력에서 유도**한다. 도구는 `scripts/palette-advisor.py`.

```bash
P=~/.config/opencode/skills/design-craft/scripts/palette-advisor.py
python3 $P --subject "위내시경 전 처치 안내" --medium card --mood "차분한, 신뢰"   # 후보 3개 + 대비 검사
python3 $P --family clinical-cool --medium deck --write build/tokens.colors.css  # 계열 확정 후 토큰
python3 $P --report build/tokens.css                                            # 기존 토큰 대비 검사
```

## 1. 색을 유도하는 입력 (5개)

색을 "느낌"으로 고르지 않는다. 아래 5개를 먼저 확정하고 그 결과를 `visual-direction.md` 에 한 줄로
남긴다(나중에 왜 이 색인지 검증할 수 있어야 한다).

| 입력 | 예 | 색에 미치는 영향 |
|---|---|---|
| **주제·도메인** | 건강검진 안내 / 요리 레시피 / 미국주식 레터 / 파이썬 워크북 | 색 계열(hue family)을 결정한다 |
| **청중** | 환자(비전문) / 동료 의사 / 투자자 / 학생 | 신뢰·친절·분석적 톤 → 채도·온도 |
| **매체·출력** | 화면 / 인쇄 PDF / 카드 1080² / 덱 16:9 / 흑백 인쇄 | 인쇄면 채도를 낮춘다(CMYK 안정) |
| **배경·기존 자산** | 브랜드 로고, 기존 사이트, 사진 배경 | 악센트·표면이 여기에 맞물려야 한다 |
| **무드·금기** | "조용한", "권위 있는", "만화 같으면 안 됨" | 후보 랭킹 + 제외 계열 |

**배경이 이미 있으면 배경이 이긴다**: 사진·로고·기존 브랜드 색이 있으면 그 색의 보색·동일 계열로
악센트를 잡는다(배경에서 색을 뽑아 쓰는 게 가장 덜 티 나는 방법이다).

## 2. 구조 규칙 (모든 계열 공통)

1. **지배색 1 + 악센트 1** — 악센트를 2개 이상 쓰면 즉시 싸구려가 된다.
2. **표면 3단** — `surface-0`(바탕) > `surface-1`(교차 섹션) > `surface-2`(올라온 면). 셋은 같은 색상의
   밝기 차이다(색상은 그대로, L 만 이동).
3. **잉크는 순수 검정이 아니다** — 표면의 색온도를 물려받은 오프블랙(`#17140F`, `#0F171C`).
4. **텍스트 3단 대비 사다리** — text-1 ≥ 10:1, text-2 ≥ 5:1, text-3 ≥ 4.5:1 (본문 최소선).
5. **인쇄면 채도를 낮추고 색만으로 정보를 구분하지 않는다** — 강조는 굵기·괘선·여백으로도 표현.
6. **금지**: 보라-인디고 계열(`design-lint.py` 의 `ai-purple` HIGH), 균등 배분 팔레트, 순수 `#000`/`#fff`.

## 3. 계열 카탈로그 (10종)

`palette-advisor.py --list` 로 같은 표를 출력한다. 표면·잉크는 계열의 골격이고, 나머지 토큰(테두리·
악센트 quiet·반대색 표면)은 스크립트가 유도하며 **대비는 실행 시 실제로 계산해 PASS/FAIL 을 낸다**.

| 계열 | 언제 쓰나 (키워드) | 표면0 | 잉크 | 악센트(대안) | 인쇄 |
|---|---|---|---|---|---|
| `warm-clay` | 요리·카페·가족·생활·수공예·전통 | `#F4EFE8` | `#17140F` | `#B33A0B` (`#8A5A2B`) | o |
| `clinical-cool` | 의학·임상·검진·논문·데이터·통계 | `#F6F8F9` | `#0F171C` | `#0E7490` (`#155E75`) | o |
| `deep-ink` | 금융·투자·부동산·법률·정부·보고서 | `#F7F6F3` | `#101828` | `#A16207` (`#1D4ED8`) | o |
| `forest-field` | 건강·습관·운동·영양·환경·여행 | `#F5F6F1` | `#16201A` | `#16543A` (`#3F6212`) | o |
| `oxblood-archive` | 역사·문학·출판·교재·기록·학회 | `#F6F2EF` | `#1B1113` | `#8C1C1C` (`#7C2D12`) | o |
| `plum-rose` | 상담·돌봄·마음·회복·기념일·취미 | `#F8F4F7` | `#17111A` | `#9D174D` (`#7A2E5A`) | o |

같은 계열이라도 `--seed` 에 따라 악센트가 **주/대안 중 하나로 갈린다** — 그래서 "같은 계열, 다른 인상"
이 가능하다. 계열까지 완전히 같으면 그때는 `--exclude <name>` 으로 강제로 비켜 간다.

## 4. 반복 감지 (히스토리)

`--write`/`--record` 는 `~/.cache/design-craft/palette-history.jsonl` 에 `{시각, 계열, 악센트, 주제, 매체}`
를 append 한다. 다음 호출부터 스크립트가

- 최근 사용 계열을 상단에 출력하고,
- 후보에 `⚠ 최근에 씀` 을 붙이고,
- `--exclude-recent` 를 주면 계열당 **-4점**을 깎는다.

강한 키워드 적합이 이기면 경고만 남기고 같은 계열을 쓸 수 있다(그게 맞는 선택일 때도 있다). 그래도
**직전 산출물과 같은 표면+같은 악센트**가 나오면 그건 실패다 — `--exclude` 또는 `--seed` 로 비켜 간다.

## 5. 검증 (넘기기 전)

```bash
python3 $P --report build/tokens.css          # 모든 표면 × text-1/2/3/accent 대비 PASS
python3 $P --report src/styles/tokens.css     # 기존 산출물을 리팩터할 때
```

- **기준 배경은 `surface-2`(가장 어두운 표면)** 다. 카드·표는 `surface-2` 위에 얹히므로 여기서
  대비가 가장 낮다. `--report` 는 surface-0·1·2 를 모두 출력한다(실측: surface-0 만 맞추고 만든
  팔레트가 카드 안에서 3.61:1 로 떨어져 `page-check.sh` MED 를 받았다 → surface-2 기준으로 맞춘 뒤
  0 HIGH/0 MED). 스크립트는 surface-2 에 맞춰 text-2 ≥5:1 · text-3 ≥4.5:1 · accent ≥4.5:1 을
  보장하고 **명도 사다리**(text-1 ≤ text-2 ≤ text-3)도 검사한다.
- 대비는 **계산값**이 기준이다(눈으로 판단하지 않는다). FAIL 이 하나라도 있으면 스크립트가 exit 1.
- `page-check.sh` 도 렌더 후 대비를 다시 본다 — 토큰이 통과해도 그라디언트·사진 위 텍스트는 깨진다.
- 색은 **토큰 파일 한 곳**에만 있다. 컴포넌트의 hex 하드코딩은 `design-lint.py` 가 MED 로 잡는다.
  **`design-lint.py --tokens` 에는 그 표면의 토큰 파일을 넘긴다** — 한 디렉터리에 다른 표면의 토큰
  파일이 같이 있으면 그 hex 들이 "토큰에 없는 hex" MED 로 뜬다(스크래치 디렉터리에서 흔한 함정).
