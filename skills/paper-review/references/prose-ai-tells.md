# Prose pass — what counts as AI 티, 숫자 나열, 과단정

Read this when the prose_lint output needs interpreting, or when you are judging a line the
script did not flag.

## The principle

AI 문체는 **틀린 문장이 아니라 빈 문장**이다. 문법과 사실은 맞는데 정보가 없다. 그래서
동의어로 바꾸면 형태만 남고 공허함은 그대로다. 처방은 **삭제**, 그리고 남은 자리에 **수치나
비교**를 넣는 것. 문장을 예쁘게 만드는 일이 아니다.

## 1. AI 티 — 문장 단위 징후

| 징후 | 예 | 판정 |
|---|---|---|
| 의의 부풀리기 | "매우 중요한 역할을 한다", "plays a pivotal role" | 삭제. 무엇이 얼마나 달라지는지로 대체 |
| 빈 요약 접속 | "이를 통해", "이상의 결과로", "It is worth noting" | 대개 문장 전체 삭제 가능. 남겨야 하면 접속어 없이 사실만 |
| 수식어 인플레이션 | "다양한", "폭넓은", "주요한", "robust", "seamless" | 범위·수치로 바꾸거나 삭제 |
| 메타 예고 | "본 연구에서는 ~을 알아보고자 한다" | 초록·서론 첫 문단 1회만. 이후 반복은 전부 삭제 |
| 대조 공식 | "단순히 A가 아니라 B" | 한 원고에 2회 이상이면 문체로 읽힘 |
| 3항 나열 | "A, B, C를 제공한다" | 실제로 3개가 필요한지 확인. 2개면 2개로 |
| 문단 첫머리 접속어 반복 | 또한 / 또한 / 또한 | 하나 남기고 나머지는 문장 구조로 연결 |
| 강조 부사 | "매우", "상당히", "clearly" | 수치가 있으면 부사는 불필요 |

**한국어 특유의 함정**: "~할 수 있다"의 남용. 관찰 결과를 "~할 수 있음을 시사한다"로
모든 문장에 붙이면 논지가 사라진다. 결과 문장은 단정하게 쓰고, **해석 문장에서만** hedge를
쓴다. 문장마다 hedge가 붙어 있으면 그건 정직이 아니라 회피다.

## 2. 숫자 나열 (number dump)

한 문장에 수치 4개 이상이면 기계적으로 플래그된다. 판정 기준은 개수가 아니라 **해석의 유무**:

- 나쁨: "사망률은 9.2% 대 14.1%, OR 0.62, 95% CI 0.41–0.94, p=0.02, NNT 20이었다."
- 좋음: "조기 내시경군의 사망률이 낮았고(9.2% 대 14.1%, OR 0.62, 95% CI 0.41–0.94),
  20명을 치료하면 1명의 사망을 막는 크기였다(NNT 20)."

규칙: **한 문장에 주장 1개 + 그 주장을 지탱하는 수치 2개까지.** 나머지는 표로 보내고,
본문에서는 "Table 2"로 가리킨다. p값과 CI는 주장마다 한 번씩만 등장해야 한다 — 같은
수치가 초록·결과·논의에 세 번 나오면 그건 나열이 아니라 반복이다.

## 3. verbose

문단마다 검사할 세 가지:

1. 첫 문장이 정보를 담고 있는가 (화제 예고가 아니라 주장인가).
2. 마지막 문장이 다음 문단을 필요로 만드는가.
3. 문단을 통째로 지웠을 때 논지가 다치는가. 안 다치면 지운다.

흔한 낭비: 방법을 서론에서 한 번, 방법 절에서 또 한 번 설명; 같은 한계를 논의와 결론에 두 번;
"추가 연구가 필요하다"로 끝나는 결론.

## 4. 톤과 단정 (overclaim)

원칙: **설계가 지지하는 강도까지만 주장한다.**

| 쓰지 말 것 | 대신 | 조건 |
|---|---|---|
| 입증되었다 / 증명되었다 / proves | was associated with / suggests | 관찰 연구 |
| 인과관계를 확인했다 | 인과 추론은 제한적이다 (design 명시) | RCT·중재 아니면 |
| 모든 환자 / all patients | 이 코호트에서 / in this cohort | 표본 한정 |
| 최초로 / the first | 선행연구와의 차이를 문장으로 | 실제 검색 근거 있을 때만 |
| 명백히 / clearly | (삭제) | 거의 항상 |
| 반드시 필요하다 | 권고할 수 있다 (근거 등급과 함께) | 가이드라인 아닌 이상 |

**반대 방향도 실패다.** 핵심 결과를 "~인 경향이 있을 수 있다고 생각된다"로 쓰면 심사자는
"저자는 자기 결과를 믿는가"를 묻는다. hedge 비율이 문장의 45%를 넘으면 과잉 hedge로 보고,
결과 문장에서 hedge를 걷어낸다.

## 5. 판정 순서

1. 스크립트 출력의 HIGH부터 읽는다 — 대개 3~5개가 실제 문제다.
2. 각 줄에 "이 표현이 사실과 다르거나 근거보다 세다"고 말할 수 있는가? 못 하면 유지하고
   이유를 리포트에 적는다(스크립트 오탐은 그대로 남긴다).
3. 수정안은 **문장 하나**로 제시한다. "톤을 부드럽게"는 지시가 아니다.
4. 인용문은 원문 그대로, 위치는 줄 번호로. 심사 리포트에서 인용 없는 지적은 반박된다.
