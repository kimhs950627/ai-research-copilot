# 판형 · 조판 · 검증 (read this when 판형/토큰을 바꾸거나, 카드 수가 이상하거나, 인쇄가 어긋날 때)

## 1. 왜 이 판형인가

큐카드는 **무대에서 한 손에 들고 한눈에 훑는** 물건임. 그래서:

- A4 세로 한 장에 카드 두 장(148.3 mm). A5 한 장에 한 카드 = 종이가 두 배, A4 네 장(A6) = 글자가 작아짐.
- 본문 16 pt / 행간 1.5. 렉턴에 놓고 읽는 게 아니라 손에 들고 훑는 크기임. 14 pt 아래로 내리면
  리허설에서 눈이 미끄러짐.
- **글자를 줄여 맞추지 않음.** 넘치면 다음 카드로 이어가고 제목에 "계속"이 붙음.
- 카드 하나 = 대본의 한 섹션(`## N. 제목 — 45초`). 섹션 경계가 카드 경계라서, 카드를 넘기면
  슬라이드도 넘어감.
- 재단선은 점선 하나(가운데). 잘라서 카드 번호순으로 쌓음.

## 2. 토큰 (presentation/styles/tokens_v3.css 에서 상속)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--ink` | `#16202A` | 본문·제목 |
| `--ink-soft` | `#3A4750` | "계속" 카드 제목, 무대 지시 본문 |
| `--muted` | `#5A666F` | 카드 번호, 푸터, 표 캡션 |
| `--line` | `#D9D5C9` | 헤어라인 |
| `--cut` | `#C4BFB0` | 중앙 점선 재단선 |
| `--accent` | `#0F6E63` | eyebrow(러닝 타이틀)·§번호·불릿 기호 |
| `--caution` | `#8A6A2A` | **무대 지시** 라벨·좌측 규칙, `[큐]` 칩 |
| `--paper-2` | `#F5F3EE` | 무대 지시 바탕 (인쇄에서 옅게 나옴) |

제목은 세리프(Batang/바탕), 본문은 산세리프(Malgun Gothic). 슬라이드 덱과 같은 규칙임 —
카드가 덱과 같은 옷을 입어야 발표장에서 이질감이 없음.

**한국어 줄바꿈 규칙(전역 규칙)**: `body` 에 `word-break: keep-all; line-break: strict;
overflow-wrap: break-word; hyphens: none`. `break-all`·`overflow-wrap: anywhere` 는 한글 어절을
쪼개므로('독일' → '독/일') 본문에 금지함. `.cbody` 에도 같은 값을 명시함. 검증은
`design-craft/scripts/page-check.sh <html>` 의 '한글 어절이 쪼개짐' 검사(문자 rect top 비교)로 함 —
2026-10-18 큐카드 두 벌 모두 0 HIGH · 0 MED(남은 LOW 는 8 pt eyebrow 와 print HTML 에 h1 이 없다는
지적뿐, 인쇄물이라 문제 없음).

토큰을 바꾸려면 `--css` 로 자기 CSS 를 넘기고 `:root` 값을 덮어씀(스킬 기본 파일은 건드리지 않음).

**테마 유도 (design-craft)**: 색·폰트는 대본마다 새로 뽑는다 — `theme-advisor.py --medium cuecard`
(기본 권장 `document-plain`, 낭독 리허설이면 `editorial-serif`; 홍보용 카드가 아니므로 `brutalist-poster`
는 쓰지 않음). 매핑은 `--color-text-1`→`--ink`, `--color-text-2`→`--ink-soft`, `--color-text-3`→`--muted`,
`--color-border`→`--line`, `--color-accent`→`--accent`, `--color-warning`→`--caution`,
`--color-surface-1`→`--paper-2`, `--font-display`→`--serif`, `--font-body`→`--sans`.

**폰트는 그 환경에 설치된 것만 쓴다(실측)**: 테마의 `--font-display`/`--font-body` 를 그대로 넣으면
렌더 지표가 달라져 **블록 하나가 카드보다 커져 탈락**한다 — 실측: Pretendard/Noto Sans KR 스택(이 기기에
미설치) → `CHECK FAILED: 1 block(s) missing`, 원래 Batang/맑은 고딕 유지 → 0. 그래서 큐카드는 테마에서
**색만** 가져오고 폰트는 설치된 계열로 끝맺거나, 바꿨으면 `make_cuecards.py` 의 블록 무손실 CHECK 를
반드시 다시 본다(글자를 줄이지 않고 대본을 나누는 기존 규칙은 그대로).

**바꾸면 안 되는 것(기하)**: `--pad-x`(인쇄 여백)·`--pad-y`·`--card-h`·`--cut`. A4 한 장에 148.3 mm
카드 두 장이 들어가는 실측 기하라, 여기를 건드리면 `check_cuecards.py` 의 A4 검증이 깨진다. 테마는
**색·폰트만** 바꾸고 조판 기하는 그대로 둔다. 검증은 `python3 $T --report <css>` (대비 PASS) +
`check_cuecards.py` (기하·카드 수) 두 겹이다.

## 3. 카드 채우기 알고리즘 (assets/paginate.js)

측정과 배치가 분리되어 있음.

1. `#src` 의 블록(문단·불릿·표행·무대지시·인용)을 문서 순서대로 읽음.
2. `#`/`##`/`---` 를 만나면 **새 카드**를 열고, 그 뒤의 블록을 하나의 run 으로 모음.
3. run 의 각 블록 높이를 **오프캔버스 스크래치 카드**(같은 폭 180 mm, 높이 제한 없음)에
   하나씩 넣어가며 실측 델타로 잼.
4. run 이 한 카드에 안 들어가면 필요한 카드 수 n = 1 + ceil((총높이 − 첫 카드 여유)/연속 카드 여유) 를
   구하고, **공정 분배**(각 카드가 남은 높이의 1/(남은 카드) 에 가장 가까워지는 지점에서 자름)로
   나눔. 그래서 2장짜리 섹션이 90 %/10 % 로 갈라지지 않고 60 %/45 % 로 앉음.
5. 마지막으로 실제 카드에 넣으면서 `getBoundingClientRect()` 로 **다시** 넘침을 확인함.
   여백은 넘침으로 세지 않음(스크롤 높이가 아니라 그려진 끝 좌표를 봄).
6. 블록 하나가 카드보다 크면 그 블록만 한 카드에 놓고 `overfull` 로 표시함(그때는 잘릴 수 있으니
   `--block-chars` 를 낮추거나 대본에 `---` 를 넣어야 함).

시트 높이가 **296.6 mm**(카드 148.3 × 2)인 이유: 297 mm 로 꽉 채우면 Chrome 이 반올림 때문에
다음 페이지를 한 장 더 만들고, 카드 한 장이 통째로 빈 페이지가 됨. 빈 꼬리 페이지는 pypdf 로 한 번 더
정리함.

## 4. 충전율 읽는 법 (`--dom-report`)

```json
{"cards":19,"sheets":10,"overfull":0,
 "fill":[64,66,50,97,...,35],
 "titles":"시간 배분 | 시간 배분+ | §1표지 | ..."}
```

- `fill[i]` = 그 카드 본문 상자의 세로 사용률(%). 40 % 미만이 몇 장이면 카드가 헐거운 것임.
- 60–97 % 가 정상. 마지막 섹션이 짧으면(예: 20초 마무리) 35 % 도 정상임.
- `overfull > 0` 이면 블록 하나가 카드보다 큼 → 조치 필요.
- `titles` 의 `+` 는 "계속" 카드. 한 섹션이 2장이면 보통 `X | X+` 로 짝지어짐.
- 헐거운 카드가 많으면 `--font-size 15`(글자를 조금 줄여 한 카드에 더 담기) 또는 대본에 `---` 로
  카드를 직접 나누는 게 낫다. 자동 요약은 하지 않음.

## 5. 검증 (두 겹)

1. `make_cuecards.py` 내장: 렌더 직후 A4 세로 크기, `카드 NN / TT` 개수, 그리고 **원문 블록이 PDF
   텍스트에 전부 있는지**(각 블록의 앞 24자 + 뒤 24자를 정규화해 검색). 카드가 넘쳐 잘리면 뒤쪽
   프로브가 잡힘 → exit 3.
2. `check_cuecards.py`: PDF 단독 검증(기하·번호 연속·페이지당 카드 수·원문 무손실). 남에게 받은
   큐카드 PDF 를 그대로 검사할 때도 씀.

보조 확인(pymupdf 가 있으면): 페이지 안 모든 텍스트 span 이 재단선을 넘지 않는지, 본문 마지막 줄이
푸터 위에 있는지. 실측 2026-10-18, 10장/19카드 · 7장/14카드에서 위반 0.

## 6. 인쇄

- A4 세로, 실제 크기 100 %, **단면**, "한 면에 1페이지". 프린터의 "한 면에 2페이지" 옵션은 금지
  (PDF 안에 이미 두 장이 들어 있음).
- 잘라서 **카드 번호순**으로 쌓음. 19장이면 마지막 면 아래쪽은 빈 종이로 나옴(헤어라인도 숨김).
- 양면 인쇄는 하지 않음 — 자른 뒤 뒷면이 뒤집혀 순서가 섞임.

## 7. 대본이 이 스킬을 벗어나는 경우

- 표를 표 모양 그대로 옮겨야 함 → `book-craft`.
- 슬라이드 그림/도표가 카드에 필요함 → 그림은 텍스트로 못 옮김. 슬라이드 참조를 `[그림 3]` 큐 칩으로
  남기고, 그림 자체는 덱(`deck-craft`)에서 봄.
- 대본이 워드의 텍스트 상자/각주 안에 있음 → 본문으로 옮겨 달라고 요청함(변환 대상 아님).
