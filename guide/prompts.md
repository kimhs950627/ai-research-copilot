# 프롬프트 15개 — 복사용

괄호 안만 바꿔 쓰세요. 각 프롬프트는 **역할 · 입력 · 규칙 · 출력 형식 · 멈춤 조건**을 갖췄습니다.
더 자세한 설명은 [`index.html`](index.html) 10장에 있습니다.

## 01 · 주제를 질문 셋으로

```
@academic-research-writing
아래 장면을 연구 질문 후보 3개로 바꿔줘.
각 후보에 PICO, 설계, 필요한 변수, 가장 큰 약점 1개.
FINER(1-5)와 데이터 적합성으로 채점하고,
가장 약한 후보를 버리는 이유를 한 줄로. 아직 원고는 쓰지 마.
장면: (한 문단)
```

## 02 · 코드북에서 변수 찾기

```
01_data/codebook의 코드북을 읽고, (결과 변수)와 (노출 변수)에
쓸 수 있는 변수를 "변수명 / 정의 / 척도 / 연도 / 결측" 표로 정리해.
코드북에 없으면 추측하지 말고 "없음"이라고 써.
```

## 03 · 분석 계획 검토

```
02_analysis/plan.md를 STROBE에 비추어 검토해.
빠진 항목·애매한 표현·심사에서 문제될 부분을 위험도와 함께.
수정 문장을 제안하되 파일은 아직 고치지 마.
```

## 04 · 복합표본 분석 코드

```
(R/Stata)로 분석 코드를 작성해. 조건:
- 복합표본설계(층·집락·가중치) 반영, 변수명은 코드북 확인 후 주석
- 원자료 수정 금지, 결측 처리 명시
- 코드 먼저 보여주고 승인 후 실행
- logs/에 패키지 버전과 실행 시간 기록
```

## 05 · 표 1 만들기

```
(노출/결과)에 따라 표 1을 만들어줘.
연속변수는 평균(SE) 또는 중앙값(IQR), 범주형은 가중 %.
결측 수를 각 변수에 표시하고, 전체 n과 분석 n을 구분해.
03_output/tables/table1.csv와 .docx로 저장해.
```

## 06 · 결과 섹션

```
표 1~3만 근거로 Results를 써줘.
문장당 숫자 최대 하나, 나머지는 표를 가리켜.
표에 없는 숫자는 만들지 말고, 없으면 "표에 없음"이라고 써.
한국어 본문 + 영어 초록 3문장.
```

## 07 · 고찰의 한계

```
이 연구의 한계를 심사자가 지적할 순서로 7개 나열해.
각 한계에 "왜 문제인가 / 어떻게 완화했나 / 남은 위험"을 붙여.
과장하지 말고, 데이터가 지지하지 않는 방어는 쓰지 마.
```

## 08 · 인용 검증

```
참고문헌을 하나씩 검증해: 존재(DOI/PMID), 주장 지지(쪽·표),
접근 수준(full_text/abstract/metadata_only).
확인 못 한 것은 "확인 불가"로 표시하고 사용하지 말라고 해.
```

## 09 · 자체 심사

```
@paper-review
원고·표·그림·덱을 심사자 관점에서 감사해.
HIGH/MED/LOW로 나누고, 각 항목에 파일·줄·수정안 3줄.
고치지는 말고 지적만 해.
```

## 10 · 숫자 대조

```
본문·초록·표·캡션의 모든 숫자를 "숫자/위치/표 값/일치" 표로.
불일치는 HIGH, 원자료 확인 필요로 표시해.
```

```

청중은 (학회/전공의/검진센터). 본문·디자인은 아직 만들지 마.
```

```

슬라이드마다 발표자 노트 30-45초.
```
